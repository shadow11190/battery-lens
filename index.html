    02 / THE SCIENCE

    健康度是容量比例，
    不是現在剩下多少電。

    滿充容量Full charge capacity÷設計容量Design capacity× 100%

    例如 4,320 mAh ÷ 5,000 mAh = 86.4%。這是電量計回報的容量估算，會受校準、溫度與廠商實作影響。電量 86%、health: 2 或 charge_counter 都不等於 86% 健康度。

    03 / HOW TO

    第一次匯出報告？從這裡開始。

    完整步驟與常見問題
    A / ANDROID

    取得手機偵錯報告

    1. 在「設定 → 關於手機」連點「版本號碼」7 次，依手機提示啟用開發人員選項。各品牌位置可能不同。
    2. 到「開發人員選項 → 擷取錯誤報告／提交錯誤報告」，選擇完整報告（若有）。
    3. 等候系統通知完成，將產生的 ZIP 儲存至裝置，再到本頁匯入。
    4. 如瀏覽器不支援解壓，先解開 ZIP，選取 bugreport-….txt 或 dumpstate_board.txt。不同檔案分開分析，避免混用來源。
    使用電腦與 ADB

    安裝官方 Android Platform Tools，連接手機並允許 USB 偵錯。在終端機執行：

    adb bugreport battery-report.zip

    報告包含哪些電池欄位由手機廠商決定；產生成功不代表一定有滿充與設計容量。不需 root；出現權限不足時不必為此解鎖手機。

    Android 官方說明 ↗
    B / IPHONE

    讀取分析記錄（實驗性）

    1. 先到「設定 → 電池 → 電池健康度」查看系統值；不同機型顯示項目可能不同。
    2. 到「設定 → 隱私權與安全性 → 分析與改進 → 分析資料」，尋找含電池欄位的近期 Analytics-… 或 log-aggregated-… 記錄。
    3. 從分享選單儲存到「檔案」，匯入本頁；也可以貼上文字。並非每份 IPS 都包含電池資料。
    4. 若沒有相關記錄，可自行決定是否開啟「分享 iPhone 分析資料」，之後等待系統產生；開啟會將分析資料分享給 Apple，不保證立即生成。

    Apple 未公開穩定的分析欄位規格。本工具嘗試讀取 MaximumCapacityPercent、NominalChargeCapacity、DesignCapacity、CycleCount（含 last_value_ 前綴）。無法保證所有 iOS 版本；不將 MaximumFCC 當成設計容量。

    Apple 分析資料說明 ↗
    為什麼顯示「資料不足」？

    報告沒有公開必要欄位、欄位值為零／不支援，或出現互相矛盾的數值。Android 優先辨識 charge_full 與 charge_full_design、POWER_SUPPLY 對應欄位、batteryFullChargeUah、batteryFullChargeDesignCapacityUah，以及 AOSP 的 Full charge。若只有滿充容量，可依官方規格手動填設計容量；不要填目前電量。

    為什麼不同報告得到不同結果？

    檔案可能包含歷史記錄、其他電池、不同時間的校準結果。本工具按檔案分開顯示；已辨識的多電池來源或衝突欄位會阻止自動計算。相同數值也無法證明來自同一電池，請核對原始來源。未支援的廠商格式會顯示資料不足。

    報告安全嗎？會被保存嗎？

    本頁沒有分析伺服器、第三方程式庫、統計追蹤或本機儲存。檔案由 Web Worker 在瀏覽器記憶體讀取，清除會終止工作並釋放引用；不保證記憶體的安全抹除。GitHub Pages 仍會處理一般網站請求（例如 IP）；報告內容不會送出。下載摘要僅含辨識欄位、來源檔名與計算結果，分享前仍請檢查。
